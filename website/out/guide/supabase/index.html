アクセス制御とセキュリティ設計 (RLS / RPC)

データベースへの直接書き込みは原則として Supabase Auth で認証された管理者のみに許可され、一般ユーザーからの更新はバリデーション付きの RPC (Remote Procedure Call) 経由に制限されています。

ロールアクセス許可範囲制御方式
一般来場者 (Anon)全テーブルの閲覧 (SELECT)、Q&A 投稿 (INSERT)、投票 (RPC)RLS (FOR SELECT USING (true)) & RPC (vote_for_target)
模擬店運営 (StallAdmin)自店舗の混雑・在庫状況の更新 (UPDATE)QRトークン検証による Auth セッション & RLS
全体管理者 (Admin)全テーブルの作成・更新・削除 (ALL)管理者ログインによる Auth セッション & RLS

セキュリティ監査テスト仕様

src/lib/Misc/audit_security.ts スクリプトは、悪意のあるクライアントからの不正アクセスや改ざんをシミュレートし、RLS ポリシーおよび RPC の防御性能を検証します。

テスト ID検証項目・攻撃内容防御メカニズム & チェックポイント
T1期間外の不正投票vote_for_target 内で app_settings の vote_start_at / vote_end_at を照合し拒絶。
T2匿名ユーザーによる直接改ざんnews や stalls_status 等のテーブル RLS が ENABLE であり、匿名書き込みがブロックされること。
T3ID 偽装・連打による多重投票RPC 内でクライアント IP x-forwarded-for のハッシュ化およびレート制限インターバル判定を行い遮断。
T4システム設定値の不正操作app_settings の RLS および tr_block_anon_update トリガーにより匿名更新を強制ロールバック。
