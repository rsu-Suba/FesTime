On-premise operation

Supabase Local (Docker) と Cloudflare Tunnels を組み合わせ、クラウド費用を一切かけずに学校や団体のPC 1台で完全オンプレミス運用を実現する実践ガイド

完全オンプレミス運用の概要とメリット

FesTime は Supabase Cloud (マネージドサービス) だけでなく、Supabase CLI を利用したローカル Docker 環境 (Supabase Local) でもまったく同一のコードベースで動作します。 さらに Cloudflare Tunnels を組み合わせることで、ルーターのポート開放や固定IP契約を行うことなく、安全に SSL (HTTPS) 暗号化された通信で来場者へサービスを公開できます。

項目クラウド運用 (Supabase Cloud)完全オンプレ運用 (Local + Cloudflare)
コストPro プラン ($25/月〜) 推奨完全無料 ($0)
データ保管場所AWS / クラウドリージョン実行委員会 / 学校内のローカル PC
同時接続・制限プラン枠に依存 (クォータ制限あり) マシンスペックと回線帯域のみに依存
セキュリティクラウド標準の保護Cloudflare による DDoS 保護 + トンネル通信
向いている環境クレカ決済やクラウド利用が承認されている学校予算制約がある、または閉域網・校内完結が求められる学校

アーキテクチャ構成

来場者や模擬店スタッフのアクセスは Cloudflare のエッジサーバーを経由し、セキュアな暗号化トンネル cloudflared を通じて本部PCのローカル Docker コンテナ群へルーティングされます。

  1. 来場者・スタッフ: https://your-domain.com または GitHub Pages のフロントエンドにアクセス
  2. Cloudflare Edge: SSL 終端、DDoS 攻撃緩和、グローバル CDN キャッシュ
  3. Cloudflare Tunnel (cloudflared): ポート開放なしでローカル PC と Cloudflare 間を暗号化接続
  4. Kong API Gateway (Port 54321): リクエストを PostgreSQL、PostgREST、GoTrue (Auth)、Storage へ中継
  5. Supabase Local (Docker): 高速なローカル SSD & メモリ上で SQL 関数・トランザクションを実行

前提環境・必要なツール

  • ホスト PC: メモリ 8GB 以上 (16GB 推奨)、macOS / Windows (WSL2) / Linux
  • Docker Desktop: または Docker Engine + Docker Compose
  • Supabase CLI: 公式コマンドラインツール
  • Cloudflare アカウント: 無料プランで利用可能 (独自ドメインまたは Quick Tunnels)
  • 有線 LAN 接続: 安定運用のために Wi-Fi ではなく有線接続を強く推奨

Step 1: Supabase Local の初期化 & 起動

リポジトリのルートディレクトリで Supabase CLI を初期化し、Docker コンテナ群を起動します。

# 1. Supabase CLI のインストール (Mac の場合)
brew install supabase/tap/supabase

# 2. プロジェクトの初期化
supabase init

# 3. ローカルコンテナ群を起動 (Docker Desktop が起動している必要があります)
supabase start

起動が完了すると、ターミナルに以下のような接続情報が表示されます :

データベースの構築 & アカウント設定

  1. ブラウザでローカル Supabase Studio http://localhost:54323 を開きます。
  2. 左メニューの 「SQL Editor」 を開き、プロジェクト内の SQL/Full.sql を貼り付けて実行します。
  3. 続いて SQL/06_generate_votejson.sql を実行し、結果を public/data/vote.json に配置します。
  4. 左メニューの 「Authentication」 → 「Users」 から、全体管理者と模擬店管理者の2アカウントを作成します。

Step 2: Cloudflare Tunnels による安全な外部公開

ローカルの API Gateway http://localhost:54321 を、ルーターのポート開放なしでインターネット上に公開します。

方法 A: Quick Tunnel (検証・即時テスト用 / ドメイン不要)

Cloudflare 公式の cloudflared をインストールして以下のワンライナーを実行するだけで、一時的なランダム公開 URL https://xxxx.trycloudflare.com が即座に発行されます。

# cloudflared のインストール (Mac の場合)
brew install cloudflared

# Kong API Gateway を一時公開
cloudflared tunnel --url http://localhost:54321

方法 B: 名前付きトンネル (本番運用推奨 / 独自ドメイン)

固定ドメイン (例: your-domain.com) で運用する場合は、Cloudflare Zero Trust ダッシュボードまたは CLI で名前付きトンネルを作成します。

# 1. Cloudflare にログイン
cloudflared tunnel login

# 2. トンネルの作成
cloudflared tunnel create festime-tunnel

# 3. ドメインのルーティング設定
cloudflared tunnel route dns festime-tunnel your-domain.com

# 4. 設定ファイル (~/.cloudflared/config.yml) を作成
tunnel: <TUNNEL_UUID>
credentials-file: /Users/<USER>/.cloudflared/<TUNNEL_UUID>.json

ingress:
  - hostname: your-domain.com
    service: http://localhost:54321
  - service: http_status:404

# 5. トンネルを常駐起動
cloudflared tunnel run festime-tunnel

Step 3: アプリ環境変数の接続設定

Cloudflare Tunnel で発行された公開 URL、およびローカル Supabase の anon key を .env に設定します。

.env
# Cloudflare Tunnel 経由の公開 API エンドポイント
NEXT_PUBLIC_SUPABASE_URL=https://your-domain.com
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...

# 認証設定
NEXT_PUBLIC_ADMIN_EMAIL=admin@example.com
NEXT_PUBLIC_BOOTH_ADMIN_EMAIL=booth@example.com
NEXT_PUBLIC_BOOTH_ADMIN_PASSWORD=your_secure_password

設定完了後、フロントエンドを通常通りビルドして GitHub Pages や校内 Web サーバーにデプロイすれば、完全オンプレミス運用での本番稼働が開始されます。

本番運用のチェックリスト & Tips

運用項目推奨対策 & ベストプラクティス
PC のスリープ防止文化祭本番中に PC がスリープすると全サービスが停止します。macOS の場合は caffeinate -d -i -m -u コマンドを実行するか、OS の省電力設定でスリープを無効化してください。
有線 LAN & UPS (無停電電源)Wi-Fi は混雑時に切断されるリスクがあるため、サーバー PC はルーター直結の有線 LAN を使用してください。万一のブレーカー落ちに備え、ノート PC (バッテリー稼働可能) をサーバーにするのが最適です。
投票・データの定期バックアップsupabase db dump -f backup_$(date +%Y%m%d_%H%M%S).sql を定期実行 (または cron 設定) して、投票データや落とし物ログを定期的に別ストレージへ退避してください。
Cloudflare キャッシュの活用Cloudflare ダッシュボードの「Caching」ルールで静的アセットや公開画像キャッシュを有効化することで、校内回線への下りトラフィック負荷を 90% 以上削減できます。
